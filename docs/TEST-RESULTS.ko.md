# Hermes 비서·Pickle 비서 대화 버그 시험 — 2026-10-31

실제 Hermes Hermes 비서와 Mac Pickle Pickle 비서를 연결해 가상 자료로 왕복 시험했다. 단위 테스트만으로 성공을 판단하지 않고 실제 화면, 중계 서버의 업무 상태와 응답을 함께 확인했다.

| 설치된 운영 코드로 백그라운드 전달 | 실제 업무 completed, 화면 응답 확인 |
| 처음부터 Hermes 비서에게 물어보라는 구체적 지시 | 화면 검증 후 가상 노트 답변 수신 |

허락 말풍선 시험은 사용자 지시로 수행한 **가상 데이터 시험**이다. 실제 개인정보 공유 승인을 대신 생성하는 기능으로 사용하면 안 된다.

## 수정한 문제

- 전면 입력은 다른 앱 타이핑을 방해했다. 이제 창을 올리거나 물리 키보드를 쓰지 않고 실제 피클 입력란의 백그라운드 붙여넣기 메뉴를 사용한다.
- 드라이버 업데이트로 바뀐 접근성 요소 토큰 형식을 처리했다. 화면에서 접힌 긴 문장은 실제 입력란 전체 접근성 값으로 대조한다.
- 전송 직전 입력란이 바뀌면 중단한다. 사용자 초안은 지우지 않는다. 전송 여부가 불확실하면 자동 재전송하지 않는다.
- 클립보드는 AppKit으로 RAM에만 보관하고 복원한다. 사용자가 그 사이 새로 복사하면 새 내용을 덮어쓰지 않고 중단한다.
- needs_user를 최종 상태로 고정하던 문제를 수정했다. 실제 답변을 받은 뒤 같은 업무를 완료할 수 있다. completed/failed는 재실행하지 않는다.
- CLI 종료 코드와 업무 완료 상태를 구분한다. 결과와 실제 피클 응답을 확인한다.

## 남은 한계

후속 실제 전송 시험에서 Pickle 비서가 “백그라운드 타이핑 시험 완료”를 반환하고 업무가 completed가 됐다. 사용자는 그동안 다른 앱에서 “계속 정상 입력됐어”라고 확인했다. **이 Mac에서 한 차례 동시 타이핑 시험을 통과했다.** 모든 앱·상황에서의 동작을 보장하지는 않는다. 키보드·전면 전환을 쓰지 않은 것은 코드와 실행 기록으로도 확인했다. 클립보드는 짧게 공유되므로 동시에 복사·붙여넣기하면 충돌할 수 있다.

새 Mac 전체 설치, 잠금·절전·재부팅·닫힌 앱 자동 재실행은 검증하지 않았다. 화면 기반 허락 검증은 서명된 사용자 이벤트와 같은 인증이 아니다. 노트 도구를 제한해도 Hermes 비서 기존 메모리의 완전 격리를 보장하지 않는다. 유휴 확인은 SQLite 읽기이며 5분 AI 폴링을 만들지 않았다. 캘린더 연결은 추가하지 않았다.

개인 토큰·업무 링크·대화 원문·캡처·DB는 공개 패키지에서 제외한다. 원본 시험 증거는 비공개 런타임에 보관한다. GitHub에는 비공개로 업로드했으며 외부 공개와 라이선스 결정은 하지 않았다.

## 최소화 자동 복원 — 2026-10-31 추가 검증

처음 최소화 시험에서는 화면에 보이는 창만 찾는 기존 경로가 입력 전에 중단됐다. 이후 사용자가 승인한 네이티브 복원 도우미를 추가했다.

실제 피클의 AXMinimized=true를 확인한 상태에서 운영 Hermes 비서를 실행했다. 접근성 API로 해당 채팅 창의 최소화 속성만 false로 바꾸고, 앞에서 사용하던 앱의 PID가 유지되는지 확인했다. 이어 기존 백그라운드 전달 경로로 “최소화 자동 복원 시험 완료”를 받아 task completed와 delivery confirmed, 실제 채팅 응답을 확인했다.

복원은 보이는 채팅 창이 없을 때만 한 번 시도한다. bundle ID·정확한 채팅 제목·SceneWindow 식별자가 맞는 창이 전체 실행 앱에서 하나여야 한다. 앱 활성화·Raise·키보드·다른 앱 조작을 하지 않는다. 복원 읽기 검증·활성 앱 검증·동일 PID의 실제 창 재탐색에 실패하면 전송하지 않는다. 복원 후 자동으로 다시 최소화하지 않는다.

Hermes 비서→Pickle 비서 전달과 Pickle 비서 질문의 실제 화면 검증 경로에 같은 복원 전처리를 연결했다. 이번 실제 최소화 왕복은 업무 전달에서 검증했고, 질문 검증 연결은 공통 창 검색 테스트와 코드 검사로 확인했다. 새 Mac·잠금·절전·피클 종료 자동 실행은 여전히 미검증이다. 이번 복원 시험 중 동시 타이핑의 사용자 피드백은 따로 받지 않았으며, 앞선 일반 백그라운드 전달의 동시 타이핑 성공과 구분한다.

최종 로컬 테스트: 운영 소스 99개, 공개 패키지 105개 통과. 공개 패키지에서는 설치 소유자가 별도 명시 동의한 경우에만 최소화 복원을 활성화한다.

## 꺼진 피클 자동 실행 — 2026-10-31 추가

사용자가 피클을 완전히 종료한 상태를 프로세스 조회로 확인한 뒤, 운영 Hermes 비서가 지정된 설치본을 `open -g -a`로 자동 실행했다. 로그인 상태와 기존 Pickle 비서 채팅이 유지됐고 실행 과정의 활성 앱도 유지됐다.

초기 두 시험에서는 실행 자체는 성공했지만 재실행 직후 붙여넣기 메뉴를 찾지 못해 전송 전에 중단했다. 메뉴 단순 대기로 해결되지 않아 실제 입력란을 한 번 백그라운드 선택하고 새로운 캡처에서 메뉴를 여는 방식으로 보완했다. 그 뒤 재실행된 창에서 실제 업무 completed와 “자동 실행 후 입력 확인” 답변을 확인했다. 실패 시험은 철회했고 실제 업무를 중복 실행하지 않았다.

자동 실행은 별도 `native_app_launch_consent`와 `pickle_app_path`가 있을 때만 사용한다. 실행 중인 같은 앱은 중복 실행하지 않고, 설치된 .app의 bundle ID를 검증한다. 한 번 실행 후 최대 약 30초 동안 창 준비와 활성 앱 유지를 확인하고, 이후 실제 채팅·빈 입력란·전송 직전 전체 값 검증을 통과해야 보낸다. 로그인·업데이트 화면을 자동 처리하거나 잠금을 해제하지 않는다. 종료된 앱 실행과 최소화 복원의 동의는 별개다.

운영 소스 107개·공유 준비본 115개 로컬 테스트 통과. Mac 절전·잠금·로그아웃 후 전체 복구, 새 Mac과 다른 앱 버전은 미검증이다.

### 마지막 통합 시험 결과

사용자가 다시 완전히 종료한 뒤 수정본으로 시험했으나, 자동 실행은 성공하고 첫 붙여넣기는 다시 실패했다. 입력란 선택이 재실행 직후 문제를 안정적으로 해결했다고 볼 수 없다. 앞선 전달 성공은 재실행된 창에서 별도로 확인한 결과다. 이번 작업도 전송 전에 중단하고 철회했다. 현재 **앱 자동 실행·로그인 유지는 확인했지만, 완전 종료부터 첫 답변까지 무인 왕복은 미해결**이다. 일반 백그라운드 전달과 최소화 복원의 앞선 검증을 이 결과와 구분한다. 전면 활성화 우회는 실행하지 않았으며 사용자의 별도 선택을 기다린다.

## 최종 성공: 정상 종료 → 자동 실행 → 시작 준비 → 실제 답변

사용자가 네이티브 정상 종료와 시작할 때만 잠깐 활성화하는 방식을 명시적으로 승인한 뒤 시험했다. 피클 정상 종료와 프로세스 소멸을 확인하고 운영 Hermes 비서를 실행했다. 설치본 자동 실행 → 기존 로그인·채팅 복귀 → 입력란을 준비하는 동안 잠깐 활성화 → 원래 앱 복원 → 백그라운드 입력·전송 → “자동 실행과 연결 최종 확인” 실제 응답과 task completed·delivery confirmed까지 한 흐름에서 성공했다.

중간에 발견한 AppKit 활성 앱 상태의 갱신 지연은 OS Window Manager의 현재 활성 프로세스를 동기적으로 직접 읽도록 수정했다. 이 Mac에서 제공되는 Carbon GetFrontProcess/GetProcessPID를 사용하며, API가 없거나 읽기 실패 시 중단한다. 원래 앱 복원을 실제로 검증하지 못하면 계속하지 않는다. 클립보드 도우미의 활성 앱 확인에도 같은 최신 읽기를 적용했다.

**완전 재실행 직후에는 백그라운드 전용 방식만으로 입력이 불안정했다.** 이번에 성공한 방식은 별도 `native_launch_warmup_consent`가 있는 설치에서 새로 실행한 앱만 잠깐 활성화한 후 원래 앱으로 돌아오는 방식이다. 이 순간 타이핑은 잠깐 끊길 수 있고, 동시 타이핑의 사용자 체감 시험은 따로 하지 않았다. 이미 켜진 앱의 일반 전달이나 최소화 복원에는 이 활성화를 적용하지 않는다. 활성화 중에는 실제 빈 입력란을 한 번 선택만 하고 텍스트 입력·붙여넣기·전송은 하지 않는다.

정상 종료 코드는 이번 가상 시험 준비에만 사용했으며 운영 복구 도우미는 실행 중인 피클을 종료하지 않는다. 로그인·업데이트 자동 처리, Mac 절전·잠금 해제는 포함하지 않는다. 검증은 이 Mac의 한 설치·현재 로그인 상태에 한정한다. 최종 로컬 테스트는 운영 116개·공유 준비본 125개 통과다.


## 별도 파일 요청 워커 — 추가 검증

허용된 파일 목록 → 비서의 파일명·고유 marker 표시 → HTTP activate → 실제 요청 말풍선 확인 → 고정된 background computer-use 첨부 → 비서의 가상 MD 수신 확인과 DB confirmed까지 실제 왕복했다. 단순 스킬 문서와 달리 요청 처리 워커가 실제 파일을 첨부하는 경로다. 기존 일반 질문의 원문 금지·질문별 허락은 유지한다.

Mac 상시 서비스에서는 Documents 디렉터리 나열이 PermissionError로 실패했다. 소유자가 이미 허락한 컬렉션의 정확한 상대 파일명 목록을 로컬에서 생성해 디렉터리 열람 없이 알려진 파일을 검증하도록 보완했고, 실제 외부 파일 목록 API의 HTTP 200을 확인했다. 새 파일은 기존 범위를 유지하는 refresh 명령으로 목록을 갱신해야 한다.

파일 선택창의 별도 CGWindowID는 접근성 창에 대응하지 않았다. 실제 Pickle 채팅 AXWindow 아래의 AXSheet를 사용한다. 창 간 키보드 라우팅도 거절되어 키보드·클립보드·활성화 대신 위치 메뉴와 폴더 AXOpen만 사용한다. 폴더 AXOpen이 오류를 반환하고 실제 이동하는 경우는 재동작하지 않고 실제 위치 값으로 대조한다. 화면 밖 채팅 이력의 불완전 표시와 실제 트리 잘림을 구분하며 필요한 입력·첨부 요소는 각각 검증한다.

활성 앱 변경을 감지한 실제 이미지 시험은 파일 열기 전에 중단했고, 실제로 열어 둔 시험 선택창을 취소한 뒤에만 재시험했다. 사용자 초안·불확실 전송을 자동 복구하거나 재전송하지 않는다. 이 보호 규칙 때문에 실행 중 앱 전환은 실패 원인이 될 수 있다. 다른 앱에서의 동시 타이핑·다른 Mac·파일 형식·다중 첨부·대용량 파일의 반복 안정성은 별도 검증 대상이다.

최종 자동 테스트는 소스 134개·공유본 143개 통과다. 범위 밖 파일·채널 변경·철회·만료·심볼릭 링크·중복 전송·전송 중 오류·잠금 충돌·사용자 초안·파일 변경을 다룬다. 공유본에는 개인 자료나 전용 허용 규칙을 넣지 않는다.

추가로 가상 PNG도 같은 요청 프로토콜에서 실제 이미지 첨부·비서의 수신 확인·DB confirmed까지 통과했다. 종료 시 가상 파일 컬렉션을 허용 정책에서 제거했다. 실제 자료를 사용한 대량 전달·외부 게시·예약은 이 시험에 포함하지 않았다.


## 계층 보기의 동명 폴더 구분

상위 경로와 현재 폴더에 이름이 같은 폴더가 있으면 전체 파일 선택창에서 이름만 비교하던 코드가 모호한 항목으로 판단하고 업로드 전에 중단했다. 현재는 유일한 AXBrowser의 가장 오른쪽 AXList 안에서만 다음 폴더·파일을 찾고 매 단계 위치 값을 확인한다. 현재 열에 항목이 없으면 상위 열의 동명 항목으로 대체하지 않는다. 이는 왼쪽에서 오른쪽으로 배치된 macOS 계층 보기에 한정한다.

중복 폴더 이름이 존재하는 실제 승인된 이미지 경로에서, 비서의 파일 요청 → 화면 검증 → 올바른 폴더·파일 탐색 → 첨부 전송 → 실제 이미지 수신 확인 응답까지 검증했다. 실제 파일명·폴더·대화·이미지는 공유본에 포함하지 않는다. 업로드 전 실패 시 이번 실행이 연 선택창만 취소하며, 업로드가 시작됐을 수 있거나 초점이 바뀌면 정리나 재전송을 자동 수행하지 않는다.

추가 회귀 테스트는 상위·현재 열의 동명 항목, 현재 열에 없는 항목, 현재 열 자체/항목의 모호성, 업로드 전후 선택창 정리의 차이를 다룬다. 최종 소스 138개·공유본 147개 테스트 통과.
