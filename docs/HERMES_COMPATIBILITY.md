# Hermes 호환성 보완

브리지는 설치된 Hermes 소스 파일을 수정하지 않는다. 브리지가 사용하는 backend 인스턴스에만 어댑터를 붙여, 화면 요소 목록과 해당 화면의 snapshot ID·요소 토큰을 같은 응답에서 보관한다. 다른 Hermes 프로세스나 backend 인스턴스에는 적용하지 않는다.

## 보완하는 문제

일부 Hermes 캡처 함수는 요소 토큰을 저장하지만 snapshot ID를 남기지 않는다. 드라이버가 개별 토큰 대신 snapshot ID와 요소 번호를 보내면, 브리지가 방금 본 요소를 안전하게 지목하지 못할 수 있다. 어댑터는 구조화된 요소 응답을 요청하고 같은 응답의 식별 정보를 유지한다. 모델이 화면을 본 뒤 새 캡처를 끼워 넣어 다른 화면의 번호를 사용하는 방식은 쓰지 않는다.

실제로 받은 요소 번호에만 토큰을 만들며, 창이 바뀌거나 캡처가 실패하면 이전 정보를 지운다. 필요한 내부 함수나 driver의 구조화된 응답 지원이 없으면 중단한다. 승인 callback·권한 모드·사용자 동의·파일 접근 범위는 바꾸지 않는다.

## 검증 범위

2026-11-01 기준 Hermes 커밋 `8068c09432d3e7a23d30aa5f4f7d5a17783f8668`의 원본 캡처 함수를 분리해 비교했다. 현재 Mac에서 실제 드라이버의 화면을 읽는 시험에서는 원본 함수와 어댑터 조합이 요소 목록과 snapshot ID를 유지했다. 이 시험은 클릭·붙여넣기·전송·모델 호출을 하지 않았다. 당시 화면에서는 입력란이 식별되지 않아 실제 입력 성공을 확인한 것은 아니다.

가상 화면에서는 원본 방식과 수정된 방식 모두 어댑터를 통해 토큰 지정·메뉴 붙여넣기·클립보드 복원을 통과했다. 창 변경·잘못된 응답·알 수 없는 요소 번호에서 입력을 중단하는 것도 검사한다.

다른 Mac에서의 설치부터 실제 질문·파일 전달까지는 별도 검증해야 한다. 특정 Hermes 버전 전체를 지원한다고 보증하거나, Hermes를 최신으로 업데이트하기만 하면 해결된다고 단정하지 않는다. [설치 전 점검](PREFLIGHT.md) 후 실제 앱에서 가상 데이터로 전송과 수신을 확인한다.
