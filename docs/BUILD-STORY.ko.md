# Hermes 비서와 Pickle 비서 연결 과정

목표는 텔레그램에서 대화하는 Hermes 비서 Hermes 비서가 Pickle 비서 Pickle 비서에게 일을 맡기고, Pickle 비서는 사용자가 허락한 질문만 Hermes 비서에게 물어보게 하는 것이다.

실제 연결은 **Mac 로컬 중계 서버 + ngrok 고정 HTTPS 주소 + 피클 앱 백그라운드 입력**으로 만들었다. 텔레그램 봇끼리 메시지를 교환하는 구조가 아니다. 텔레그램은 Hermes 비서에게 일을 맡기는 기존 창이며 별도 알림 봇은 상태만 알린다. 기존 Hermes 비서 봇 웹훅·폴링은 변경하지 않았다.

1. Hermes 비서가 사용자 지시 범위의 작업을 발행한다. 짧은 비밀 링크에는 해당 작업만 읽고 결과를 제출할 권한이 있다.
2. Hermes 비서가 Pickle 비서 채팅의 빈 입력란을 확인하고 백그라운드 붙여넣기 메뉴로 링크를 전달한다. 물리 키보드나 전면 전환은 사용하지 않는다.
3. Pickle 비서가 HTTP로 작업을 읽어 수행하고 결과를 중계 서버에 제출한다. Hermes 비서는 실제 상태와 화면 응답을 확인한다.
4. Pickle 비서가 사용자 정보가 필요하면 질문을 등록한다. 초안 등록만으로 노트를 조회하지 않는다.
5. 사용자의 구체적 “Hermes 비서한테 … 물어봐줘” 또는 질문 뒤 “그건 Hermes 비서한테 물어봐”를 실제 피클 화면에서 확인한 뒤 그 질문에만 짧은 조회 권한을 준다.
6. Hermes 비서가 지정한 Markdown 자료를 읽기 전용 도구로 검색해 최소한만 답한다. Pickle 비서는 답을 받고 원래 업무를 이어 완료한다.

클립보드는 사용자가 승인한 AppKit 도우미로 RAM에 보관·복원한다. 내용은 파일이나 모델에 보내지 않는다. 사용자가 새로 복사하거나 입력란을 바꾸면 중단한다. 모호한 전송은 자동 반복하지 않는다.

운영 파일은 ~/Library/Application Support/PickleHermesBridge에 설치했고 로그인 자동 시작을 설정했다. 실제 옵시디언 원본은 이동·복사하지 않는다. 유휴 상태에서 AI가 5분마다 조회하지 않는다. 지속 위임 규칙은 사용자가 지정한 업무 범위만 저장하며 임의로 정보 조회 허락이 되지 않는다.

[실제 시험 결과와 한계](TEST-RESULTS.ko.md)를 참고한다. 이 Mac에서 실제 전달 중 다른 앱 타이핑이 정상임을 사용자 피드백으로 확인했다. 새 Mac·절전·잠금 환경은 추가 확인이 필요하다.

다른 사람이 쓸 공개 준비본은 이 공개 준비 디렉터리에 분리했다. 운영 비밀·노트·로그를 제외했으며 설치·동의 도우미, 테스트와 문서를 포함한다. GitHub 비공개 저장소에 업로드했다. 외부 공개는 하지 않았다.

추가로 피클 최소화 시 창 자동 복원을 적용했다. 실제 최소화 상태에서 복원·전달·답변 완료와 활성 앱 유지까지 확인했다. 사용자가 허락한 설치에서만 사용하며 종료·잠금·절전 복구로 확대하지 않는다.

2026-10-31 꺼진 앱 자동 실행 경로를 추가했다. 사용자가 완전히 종료한 상태에서 설치본 자동 실행·로그인 유지·기존 채팅 복귀를 확인했다. 재실행 직후 메뉴 문제는 입력란 백그라운드 선택으로 보완했고 실제 답변도 확인했다. 상세 단계와 검증 범위는 시험 문서를 따른다.

최종 통합 시험에서는 별도 동의된 새 실행 직후 입력란을 준비하는 동안 잠깐 활성화·원래 앱 복원을 포함해 정상 종료 상태부터 실제 메시지 왕복에 성공했다. 평소 전달은 계속 백그라운드이며, 시작 준비 순간에는 타이핑이 잠깐 끊길 수 있다.
